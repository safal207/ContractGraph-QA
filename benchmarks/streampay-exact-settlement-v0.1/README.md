`boundedVerdict: UNBOUND`, never `PASS`.

## Model and invariants

`Paused` represents the production state `is_active == true && paused_at > 0`:

```text
Created -> Active <-> Paused -> Cancelled
             |          |
             +----------+-----> Ended
```

This diagram is descriptive. The evidence gate uses only states and
transitions generated by the executable `apply_action` model; there is no
separate hand-authored lifecycle PASS disconnected from reachability.

The fixed model uses the same boundary for pause, settle, batch-equivalent
settlement, and cancel:

```text
end_bound = end_time == 0 ? now : min(now, end_time)
accrual_bound = paused_at == 0 ? end_bound : min(end_bound, paused_at)
```

It models `pause`, `resume`, `settle`, `batch_settle`, and `cancel`, including
permissionless settlement and payer-only lifecycle actions. Economic state is
split into:

- `recipient_accounted`;
- `payer_returned`;
- `remaining_custody`;
- `eligible_active_seconds`, advanced by an independent phase/time oracle.

`payer_returned` is the model's conceptual terminal allocation of the retained
remainder; it does not claim that these contract methods perform a token
transfer that is absent from the native implementation.

The principal invariants are:

```text
initial_value
= recipient_accounted + payer_returned + remaining_custody

after each accepted pause / settle / batch_settle / cancel:
recipient_accounted
= min(initial_value, rate * eligible_active_seconds)
```

The earned-time oracle never reads the payout cursor, payout formula, or
`paused_at`; therefore the earned/unearned check is not a restatement of the
implementation under test. This equality catches both overpayment and
underpayment/return of already-earned value. Resume is non-value-moving, so the
equality is checked on the next accepted value-moving action. Rejected actions
must be atomic. The verifier also checks non-overlapping paid intervals,
bounded end caps, natural-end terminality, terminal immutability,
authorization, pause cursor advancement, stale pause cleanup, and terminal
allocation.

## Deterministic bounded coverage

There is no randomness and no seed. State exploration uses exact immutable
state equality, action timestamps in sorted declaration order, and maximum
transition depth `4`.

| Configuration | Rate | Initial value | End | Graph witnesses |
| --- | ---: | ---: | ---: | --- |
| bounded | 10 | 1,000 | 10 | 2, 10, 11 |
| unlimited | 10 | 1,000 | 0 | 2, 100 |
| small balance | 10 | 15 | 1 | 1, 2 |

Executable scenario checks additionally cover active `end-1`, exact end,
`end+1`, and very late settlement. The nine required paused regressions are:

1. bounded pause after natural end;
2. pause -> settle;
3. pause -> cancel;
4. pause -> settle -> cancel;
5. unlimited pause -> very-late settle;
6. pause -> batch settle;
7. pause -> resume after natural end -> pause;
8. pause exactly at natural end;
9. low-balance/high-rate pause after end.

Controls cover settle -> settle, settle -> cancel, cancel -> settle,
unauthorized pause, unauthorized cancel, and permissionless settle.

## Paused-defect negative control

The executable mutant reproduces the reviewed pre-fix behavior:

- pause accounts raw `now - start_time` and leaves the cursor stale;
- pause does not terminalize at natural end;
- settle, batch settle, and cancel ignore `paused_at`;
- terminal paths retain stale pause state;
- resume can reset the cursor after natural end.

The verifier passes only if all nine repaired scenario expectations pass under
fixed semantics and fail under this mutant, and CGQA reachability exposes at
least I1, I2, I4, I6, and I7 in the mutant.

## Replay

From the ContractGraph-QA evidence worktree in PowerShell, point `PYTHONPATH`
at an exact checkout of the CGQA `v1.8.0` tag. Before committing, run the
development replay:

```powershell
$env:PYTHONPATH='C:\path\to\ContractGraph-QA-v1.8.0'
python benchmarks\streampay-exact-settlement-v0.1\verify.py
```

Expected development result is exit `0`, `semanticVerdict: PASS`,
`boundedVerdict: UNBOUND`, and `publishable: false`.

After committing both benchmark files, run the publication replay:

```powershell
$env:PYTHONPATH='C:\path\to\ContractGraph-QA-v1.8.0'
$evidenceCommit = git rev-parse HEAD
python benchmarks\streampay-exact-settlement-v0.1\verify.py --evidence-commit $evidenceCommit
```

Expected publication result is exit `0`, `boundedVerdict: PASS`, and
`publishable: true`. A different SHA, dirty benchmark file, mismatched commit
blob, wrong core HEAD/tag, or dirty tracked core checkout produces `FAIL` and a
nonzero exit. For the local review workspace the exact tag checkout is
`work/test-runs/cgqa-v180-tag`.

## Claim boundary

Even a fully bound `PASS` is exact evidence only for the declared
configurations, witnesses, actions, and depth. It is **not** a production proof
or security certification. Native Rust regressions at the exact StreamPay
target commit are the source-to-implementation binding, and GitHub CI state is
separate evidence.
